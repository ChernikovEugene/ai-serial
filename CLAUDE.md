# Инструкции для Claude

- В начале каждой сессии прочитай `docs/HISTORY.md`: там история проекта и место, где остановились.
- После заметной работы (новая функция, важное решение, смена планов) добавь в конец `docs/HISTORY.md`
  запись с датой: что сделано, что не доделано, следующие шаги. Коммить её вместе с изменениями.
- Владелец проекта пишет по-русски, отвечай по-русски.

## Совместная работа

Студия работает на сервере: **https://pari-altushka.ru**. Сервер берёт код из `main`, поэтому **пуш в `main` — это
сразу обновление живого сайта**, которым пользуется вся команда.

- Работаем прямо в `main`, без отдельных веток и pull request. Перед началом работы: `git pull`.
- **Перед каждым пушем проверь изменения у себя**: запусти студию на отдельной чистой папке данных
  (`STUDIO_DATA_DIR=/tmp/studio-test`, другой порт, например 8766), прогони `python tests/smoke_roles.py http://127.0.0.1:8766`
  и посмотри затронутые страницы в браузере. Не пушь то, что не проверено или падает.
- Изменения в базе (новые таблицы, колонки, миграции) — только добавлением: не удаляй и не переименовывай данные,
  на сервере настоящие серии команды. Если без этого никак — сначала спроси владельца.
- Перед пушем ещё раз `git pull --rebase`: в `main` мог успеть запушить второй участник или его Claude.
- Каждая заметная работа добавляет запись с датой в `docs/HISTORY.md`: кто, что сделал, что осталось.
- Настоящие данные (серии, библиотека, видео) живут только на сервере. Папка `data/` на ноутбуке — для проверки, в git её нет.

## Правки с сайта («Запусти правки»)

В студии внизу меню есть кнопка «Сообщить о проблеме»: заявка (тип, текст, снимок экрана, страница, версия сайта)
сохраняется на сайте, и её видит только админ на вкладке «Заявки». Нужные заявки админ кнопкой «Отправить в правки Claude»
превращает в GitHub Issue с меткой `правка` (снимок — только по галочке, репозиторий публичный; снимки лежат в ветке
`pravki-shots`, папка `shots/`). Закрытая задача сама отмечает заявку «Сделано».

По команде «Запусти правки» (или «посмотри правки»):

1. `gh issue list --label правка --state open` и для каждой `gh issue view N --comments`. В конце тела задачи есть
   скрытая строка `<!-- pravka: {...} -->`: там текст, страница студии (`page`, например `#/episodes/3/shots`), размер окна,
   автор и пути скриншотов (`shots`). Скриншоты посмотреть: `gh api "repos/{owner}/{repo}/contents/<путь>?ref=pravki-shots" -H "Accept: application/vnd.github.raw" > /tmp/shot.png`, затем открыть файл.
2. Правки с меткой `в работе` уже кто-то делает: пропустить, если об этом не попросили.
3. Перед работой поставить метку: `gh issue edit N --add-label "в работе"` и написать в задаче, что взято в работу.
4. Непонятную правку не угадывать: задать вопрос комментарием в задаче (`gh issue comment N`), снять метку «в работе»
   и сообщить пользователю. Ответ автор увидит в студии («Все правки» → «Обсуждение»).
5. Вносить по обычным правилам: проверить у себя, коммит сразу в `main` с `Closes #N` в сообщении коммита для каждой
   внесённой правки, запись в `docs/HISTORY.md`. После пуша задачи закроются сами и в студии станут «сделано»,
   а правка появится на pari-altushka.ru.
6. **Отчёт обязателен.** После внесения правок напиши тому, кто попросил «Запусти правки», короткий отчёт простыми словами,
   без кода. Сгруппируй по авторам правок, чтобы было видно, чьи правки внесены. По каждой правке одна строка:
   номер и суть правки (как её написал автор) → что конкретно изменилось в студии и где это увидеть. Отдельно перечисли
   правки, которые не внесены или ждут ответа, и почему. Например:

   > **Правки aristerri (внесено 2 из 3):**
   > - #12 «Кнопка сохранения не видна» → кнопка «Сохранить» теперь закреплена внизу экрана сценария.
   > - #13 «Сделать статусы крупнее» → увеличены плашки статусов в очереди и календаре.
   > - #14 «Поменять логику очереди» → не внесено: задан вопрос в задаче, ждём ответа.

   Тот же список добавь коротким комментарием в каждую задачу («Внесено: …, уже на сайте»),
   чтобы автор правки тоже увидел результат в студии.
