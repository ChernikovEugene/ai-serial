# История проекта ai-serial

Журнал работы над проектом. Новые записи добавляются в конец, с датой.
Задача файла: чтобы с любого компьютера (дома, на ноутбуке, в облачной сессии) можно было быстро вспомнить, где остановились.

## Что это за проект

«Студия сериала для TikTok»: локальное веб-приложение для производства вертикального сериала.
Сценарий серии → шоты под Veo 3 → генерация видео → просмотр и правки → очередь и календарь постинга.

- Стек: FastAPI + SQLite + чистый JS (без фреймворков), Python 3.10+.
- Запуск: двойной клик по `start.bat` (Windows), приложение на http://127.0.0.1:8765.
- Данные: папка `data/` (база, картинки, видео), в git не попадает.
- Изначально проект лежал в `E:\Projects\moviestudio` на домашнем компьютере.

## 2026-10-07: «Серии» через арки, новые статусы, PDF синопсисов (aristerri)

Этап 1 большой переделки по просьбе Арины (в чате). Старая версия сохранена меткой `backup/serii-v1`.

- **Модель:** серия принадлежит арке (`episodes.arc_id`, `position`), у серии `synopsis` и `post_text` (описание поста,
  интерфейс будет на этапе «Команда»), у арки `status` (writing / client / approved). Миграция `_migrate_arcs_v2`
  один раз раскладывает существующие серии по аркам по старому правилу (`start_number`) и ставит старым аркам
  «синопсисы согласованы». `arcs.start_number` больше не хранится по смыслу: `schedule.load_arcs` считает
  первый/последний день по сериям арки; номер внутри арки — `schedule.arc_numbers`.
- **Очередь:** серии по-прежнему 1 в день по слотам (`episodes.number`). Новая карточка встаёт в конец арки
  (`schedule.append_to_arc`), перетаскивание — `schedule.reorder_arc` (серии обмениваются днями; выложенные и
  закреплённые стоят), черновик = `number IS NULL` (раньше «бэклог»).
- **Статусы:** синопсис → синопсис у клиента → синопсис согласован → пишется ТЗ → ТЗ на проверке → ТЗ готово →
  генерация → монтаж → ролик у клиента → готов к постингу → опубликовано. Права ролей в `auth.py`
  (сценарист — до «ТЗ на проверке», монтажёр — от «ТЗ готово» до «опубликовано»).
- **Интерфейс:** страница «Серии» (`series.js`): карточки арок → арка с карточками серий (или списком), черновики,
  статус арки, «PDF для клиента» (`/api/arcs/{id}/pdf`, страница для печати в бренде PARIVISION). Старая очередь
  (`queue.js`) удалена, `#/queue` ведёт на `#/series`. На странице серии появился блок «Синопсис».
- «Статус»: этапы под новые статусы, пустые дни — «Свободный день», в описании серии без сценария — синопсис.

  и выдала 10 с (реплика была чуть длиннее 5 с). В автопромпт Omni (`breakdown.build_prompt`, только нейросети с кадрами) в конец добавлено:
  «Timeline: [0-5s] … Все реплики заканчиваются к N-0,5 с, спокойным темпом. The clip ends at exactly 5 seconds on the last frame: nothing continues after it,
  no extra scenes, no fade-out». `sync_duration` держит эти числа в ногу с длиной клипа и у промптов, правленных руками (если фраза в них есть).
- Автоподрезку по ffmpeg Евгений делать не просил, не делали. Уже собранные и закреплённые руками промпты не меняются: нажмите «пересобрать».

## 2026-10-26: видео встаёт на страницу само + звук готовности (Claude)

- Причина «надо обновлять страницу»: опрос сервера (каждые 4 с) запускался только при открытии серии или после массовой генерации, а при отправке
  одного шота кнопкой в его карточке («Отправить в Gemini Omni») не включался. Теперь `replaceShot` перезапускает опрос (`schedulePoll`).
- Когда шот закончил генерацию при открытой странице: мягкий звук (тот же `chime`, что у уведомления «серия сгенерировалась») и
  сообщение «Видео готово: шот N» (при ошибке красное «Ошибка генерации»); карточка перерисовывается и показывает ролик сама.
- Проверено: модули грузятся без ошибок в браузере, `node --check`. Весь путь «отправить → готово» с настоящей генерацией не прогонял.
  Звук браузер играет, если на странице уже было нажатие (кнопка «отправить» его даёт); во вкладке в фоне опрос идёт реже.

## 2026-10-26: кадры Nano Banana можно слать напрямую в Google (Claude)

- В «Настройках» → «Генерация» новый выбор «Кадры Nano Banana (для Gemini Omni) идут через»: Magnific (по умолчанию, как было) или Google напрямую.
  Настройка `frames_route`, переключается когда угодно; готовые кадры не меняются. Ключ Google тот же (`veo_api_key`).
- Google: `POST /v1beta/interactions`, модель `gemini-nano-banana-2.1`, `response_format: {type: image, aspect_ratio: 9:16, image_size: "1K"}`,
  референсы идут частями «Image N: имя» + картинка, промпт последним. Ответ сразу с картинкой (base64), опроса нет. Код: `frames._run_google`.
- Строго 1K: `frames.RESOLUTION = "1K"` для обоих путей, 2K/4K не запрашиваются нигде.
- Тест в `smoke_omni.py` (поддельный Google), зелёный. НЕ проверено на настоящем ключе Google: точная форма ответа с картинкой взята
  из документации, по аналогии с Omni. Если Google ответит иначе, текст ответа виден в ошибке кадра.
