# Студия сериала для TikTok

Локальное приложение для производства вертикального сериала: сценарий серии → шоты под Veo 3 → генерация →
просмотр и правки → очередь и календарь постинга.

## Запуск

Дважды кликните `start.bat`. При первом запуске он создаст окружение `.venv` и поставит зависимости
(нужен Python 3.10+ и интернет), затем откроет http://127.0.0.1:8765. Остановить — закрыть чёрное окно.

**На Mac:** дважды кликните `start.command` (нужен [uv](https://docs.astral.sh/uv/): `brew install uv`, он сам скачает
Python и зависимости). Если macOS не даёт открыть файл: правый клик → «Открыть».

При первом входе приложение попросит создать аккаунт администратора.

## Что умеет

**Серии и очередь.** Номер серии = её день выхода (1 серия в день от точки отсчёта «Серия № N выходит DD.MM»).
Порядок меняется перетаскиванием или вводом номера; при вставке остальные сдвигаются вперёд до ближайшего пустого дня.
📌 «Закрепить дату» — серия под праздник/инфоповод остаётся на своём дне при любых перестановках.
Серии без даты лежат в бэклоге. «Убрать пропуски» сдвигает серии, чтобы не было пустых дней.

**Календарь.** Месяц с сериями, праздниками и своими событиями (клик по числу). Серии перетаскиваются между днями.

**Статусы:** В разработке → Сценарий на согласовании → Сценарий согласован → В процессе генерации →
На правках визуала → Готов к постингу → Опубликовано. Видны в очереди, календаре и карточке серии.
«В процессе генерации» и «На правках визуала» ставятся автоматически при отправке в Veo и по её окончании.

**Сценарий.** Вставить текст или загрузить `.txt`. Справа живой анализ: сколько шотов, хронометраж,
какие шоты не влезают в лимит Veo (речь считается по словам, темп настраивается).
- `Шот 1`, `Шот 2`… — каждый блок = ровно один шот (ничего не делится автоматически, лишнее подсвечивается).
- Без пометок — авторазбивка (каждый абзац действия — шот, длинные реплики делятся по 8 с).
- `@` — подсказка персонажей и локаций, `@Маша:Пижама` — конкретная версия.
- `ИНТ. КАФЕ — ДЕНЬ`, `МАША: …`, `Маша (шёпотом): …`, `— …, — сказала Маша.`, `КАМЕРА: …`, `[наезд]`.
- «Версии для этой серии» — какой костюм/вариант персонажа или локации использовать во всей серии.

**Шоты.** Для каждого: оценка длительности, персонажи и их версии, локация, камера, реплики, промпт.
**Референс композиции** — картинка (раскадровка, скетч, кадр-образец): как референс композиции
(уходит в Veo первым изображением + строка в промпте) или как первый кадр видео.

**Генерация.** «▶ Отправить в Veo» — вся серия одной кнопкой (шоты без видео / с правками / все заново).
Каждый запуск — новый дубль, старые сохраняются, в монтаж идёт выбранный. Можно загрузить видео вручную.

**Просмотр и правки.** Плеер 9:16 проигрывает серию целиком из выбранных дублей. Комментарии к шоту
или ко всей серии, с таймкодом. Комментировать может любой, а **на перегенерацию шот отправляет только монтажёр**
(галочка «пометить шот на перегенерацию»).

**Перегенерация шота.** У монтажёра в «Просмотре и правках» есть панель шота: промпт можно улучшить и указать,
что не так с прошлым дублем. Каждый дубль хранит свой промпт и причину, видно число правок на шот.
Заменить можно один шот, остальные не трогаются. Старые дубли остаются, любой промпт можно взять снова.

**Озвучка.** У каждой реплики есть тип: **в кадре** (персонаж говорит, реплика уходит в промпт) или **закадр**
(голос за кадром; в видео никто не говорит, озвучка будет отдельной). В сценарии: `МАША (за кадром): …`
или `Маша (з/к): …`; в карточке шота тип выбирается списком.

## Роли и процесс
| Роль | Что делает |
|---|---|
| **Сценарист** | пишет сценарий, заполняет шоты (персонажи, локация, озвучка), ведёт библиотеку, отправляет серию «на согласование» |
| **Продюсер** | согласует сценарий; может всё и работать за любую роль; управляет командой и настройками |
| **Монтажёр** | видит только серии со статусом «Сценарий согласован» и дальше; правит промпты, генерирует, выбирает дубли, возвращает сценарий сценаристу |
| **Зритель** | смотрит и комментирует |

- Сценарий нельзя согласовать, пока в шотах есть пробелы: нет локации, пустая реплика, персонаж в кадре не из библиотеки,
  шот не влезает в лимит. Продюсер может согласовать принудительно.
- После согласования сценарист не может менять серию (только продюсер), чтобы монтажёр работал со стабильным текстом.
- Управление командой: «Настройки и команда».
- Пока приложение работает только на этом компьютере; для доступа других людей его нужно разместить на сервере.

## Проверка
Тест ролей и перегенерации (запускайте только на **пустой** базе, он создаёт пользователей и данные):
`python tests/smoke_roles.py http://127.0.0.1:8766`

## Ограничения Veo, которые учитываются
- клип 4, 6 или 8 с; с фото-референсами Veo 3.1 делает только 8 с;
- до 3 изображений-референсов на шот (композиция → персонажи → локация); их поддерживает только Veo 3.1;
- формат 9:16; предупреждения при >2 репликах и >3 персонажах в кадре.

## Veo API
По умолчанию **заглушка**: ничего не отправляется, точный запрос сохраняется в `data/media/renders/*.request.json`.
Для реальной генерации: «Настройки и команда» → «Gemini API», вставить ключ Google AI Studio.

## Совместная работа

Код общий через GitHub, а данные (`data/`: база, персонажи, видео) у каждого свои и в репозиторий не попадают.

Запустить студию с правками друга:
- пока правки в его ветке: `git fetch`, затем `git checkout имя-его-ветки`, затем `start.bat`;
- после того как pull request влит в `main`: `git checkout main`, `git pull`, затем `start.bat`.

Свои изменения делайте в отдельной ветке и отправляйте через pull request (подробнее в `CLAUDE.md`).

**Кнопка «Правка»** (справа внизу). Замечание по самой студии: текст + скриншот (⌘V / Ctrl+V или перетащить).
Правка становится задачей в GitHub Issues с меткой `правка`, поэтому её видят все участники. Во вкладке «Все правки»
видно статус (ждёт / в работе / сделано) и обсуждение. Чтобы внести правки, скажите своему Claude: «Запусти правки»
(как он это делает, описано в `CLAUDE.md`). Нужен доступ к GitHub: вход в GitHub CLI (`gh auth login`) или токен
в «Настройки и команда».
